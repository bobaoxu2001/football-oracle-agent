# 足球预测与 Kalshi 期望值流程

预测比赛时不看赔率、盘口、Kalshi 价格或其他预测市场的概率。先从球队、球员和本场条件形成主胜、平局、客胜概率，保存预测及生成时间。决定买不买时，才读取 Kalshi 买卖报价，与已保存的概率比较，计算扣费后的期望值。

本目录的人工预测与 Football Oracle 的生产模型相互独立。`sports_ev` 只计算输入概率对应的 EV 和评分，不生成球队概率，也不改写现有生产预测。

## 博扬七步法

以下权重合计100%，是初始的证据优先级，不是已校准的模型系数。不能把七个主观分数简单相加后声称得到验证过的胜率。记录数据窗口、来源和未知项；同一条伤病消息同时影响状态和进球时，避免重复计入。

| 步骤 | 初始权重 | 数据窗口 | 必查问题 |
| --- | ---: | --- | --- |
| 白面 | 15% | 当前赛季为主；上赛季只作低权重背景，通常不超过本模块证据的三分之一 | 当前可用阵容、长期联赛层级、主力能力、球队体系；身价不能代替本场实力 |
| 主客场 | 10% | 当前赛季同赛事的主客场比赛；样本不足时明确标注 | 场地、旅途、休息时间、主客表现；人工草皮等条件通过什么机制影响比赛 |
| 交锋 | 5% | 国家队最多4年；俱乐部联赛最多2个赛季 | 教练、核心球员与打法是否仍可比；过期或不可比记录不进入判断 |
| 伤病 | 20% | 最近约30天内新出现的伤病，以及分析时点的复出更新 | 按本季出场、首发、分钟和角色判断主力程度；检查替代者与同一条线是否同时受损 |
| 近期状态 | 25% | 近期最多10场同一赛事，优先最近5场；不足5场标为小样本 | 逐场调整对手强度，并考虑交手时对手的状态；留意连败后刚止颓，但单场回升只是信号 |
| 进失球 | 20% | 与近期状态采用一致的同赛事窗口 | 进失球集中还是持续；面对什么对手；红牌、点球、领先后的打法是否改变统计 |
| 新闻 | 5% | 近7天优先，必要时延伸至30天 | 官方消息或可信报道是否改变阵容、教练选择、轮换和球队运行；推测不能写成事实 |

伤病模块只对最近一个月的新变化作增量调整。更早的长期缺阵作为近期表现的基线，不再次扣分；复出改变了基线时另行记录。出场少仍要检查是否由伤病造成，不能自动等同没有作用。停赛与伤病分别列出，不受上述30天筛选限制。

近期状态只使用同一项赛事。欧冠与联赛数据不混成一个“近五场胜率”；欧冠样本不足时，国内比赛可作单独标注的球队背景，不替代欧冠窗口。每个对手的状态使用交手当时已经可知的信息，例如开局慢或近期走弱，不能用未来成绩解释过去预测。

## 复盘后的五条要求

1. **单列停赛。** 区分受伤、停赛、未报名、预计轮换和尚未确认；预计首发与确认首发分开记录。
2. **区分结果与表现。** 使用同一供应商、同一口径的 xG、射门、射正和机会质量，判断终结波动与实际能力。红牌或点球后的数据要注明。没有可靠数据时保留未知，不编造 xG。
3. **首发后必须更新。** 在开球前约1小时、官方首发公布后，复查阵型、首发中锋、中场出球组合和临时搭配的后防。记录新证据、原概率、更新概率及原因；主表每场只保留一个明确的评估版本，旧值保存在 Git 历史中，不能赛后改写预测。
4. **给大比分留下空间。** 首选比分只是一个比分。另列低比分、常规比分和大比分剧本；对防线连续失守或实力明显落后的对手，单独检查先丢球后是否被迫压上、是否失去保护。不能因为首选1-0就排除3-0、4-1。剧本没有量化权重时，不称其为完整概率分布。
5. **证据强度决定调整幅度。** 当前同层级比赛、确认首发和持续存在的具体对位证据优先。小样本、上赛季数据和单场大胜降权；不固定把所有概率收缩到1/3，也不因一条弱证据极端上调。发现反向证据后写出影响机制和调整理由。

## 预测记录

`predictions_log.csv` 字段为：

```text
date,competition,home,away,p_home,p_draw,p_away,top_score,lean,kalshi_home,kalshi_draw,kalshi_away,result,ht_result,outcome,notes
```

- `date` 使用北京时间比赛日期；`notes` 中另外记录 UTC 开球和生成时间。
- 概率使用0到1，三项合计为1；`top_score`、`result`、`ht_result` 使用主队在前的 `2-1` 形式。
- `outcome` 使用 `home`、`draw`、`away`。赛果采用常规时间含补时，与所分析市场的结算范围保持一致；加时和点球大战不能混入。
- 三个 Kalshi 字段单位为美分，是该结果的 Yes 参考价格；没有价格留空，不以0代替。真实交易判断仍需输入对应侧的可成交 ask，不能只靠该参考字段。
- 当前记录的9场为2026年10月14日凌晨的欧冠，是2026年10月13日生成的 `prospective_manual` 人工赛前判断，未经校准。价格、全场结果、半场结果、实际胜平负均留空。
- 当前可见对话没有10月12日九场完整原始预测及赛果，无法证实历史均分0.588或命中6/9。用户提供的考文垂概率和价格仅保存在计算示例中，不据此反推比赛结果。
- `notes` 使用 JSON 保存 `forecast_type`、生成时间、首发状态、比分剧本及关键证据。若录入回溯重建或未核实历史数据，标为 `retrospective`、`reconstructed` 或 `historical_unverified`，评分工具会排除这些行。

每场在主表仅出现一次。不同预测阶段不作为独立比赛累加；评分工具拒绝重复的日期、赛事、主队、客队组合。首发更新是执行本流程时必须完成的人工步骤，本工具没有定时器或自动首发抓取任务。

标为前瞻预测的记录必须有带时区的生成时间、信息截止时间和开球时间；生成及截止时间都须早于开球，截止时间不能晚于生成时间。评分工具拒绝违反此顺序的记录。

## Kalshi 计算与报价

本工具按指定的历史兼容规则估算手续费，价格 `P` 在 Python API 内使用美元，例如30.5¢输入为0.305：

```text
fee = ceil_to_cent(rate × contracts × P × (1 − P))
cost_per_contract = P + fee / contracts
win_probability = p_model（Yes）或1 − p_model（No）
EV = win_probability − cost_per_contract
ROI = EV / cost_per_contract
full_Kelly = (win_probability − cost_per_contract) / (1 − cost_per_contract)
```

默认 taker 费率0.07；`--maker` 使用0.0175，前提是该系列收取对应 maker 费。挂单未成交不产生持仓，也不能把 maker 计算当成已经成交。费率可以调整，但工具没有自动读取每个市场的手续费乘数。

**费用版本边界：** 2026年7月7日生效的[官方费用表](https://kalshi.com/docs/kalshi-fee-schedule.pdf)包含市场乘数，并将手续费与持仓成本之和向上取整至 centicent（0.0001美元）。本工具按本次要求保留“每笔手续费向上取整到美分”的保守估算，以复现100份、30.5¢手续费1.49美元的示例；不声称与当前平台逐笔账单完全一致。

Yes和No都用各自的买入价。根据[官方订单簿说明](https://docs.kalshi.com/getting_started/orderbook_responses)：

```text
No ask = 1 − Yes bid
Yes ask = 1 − No bid
```

只有一个 Yes 价格时，`1 − Yes price` 只是零价差情景。CLI会明确标注，不能将这份情景输出当成真实可成交报价。使用 `--no-prices` 提供三个 No ask，或使用 `--bids` 提供三个 Yes bid；两者不能同时使用。

美式赔率转换只是价格录入方式，不能用作球队概率：正赔率为 `100 / (odds + 100)`，负赔率为 `abs(odds) / (abs(odds) + 100)`。考文垂示例中的+228/+251/+109分别转换为约30.4878/28.4900/47.8469¢；验收命令使用其30.5/28.5/47.8¢近似值。

## 下注门槛与仓位

- 扣费后的每份EV至少0.03美元，即+3¢；比较未四舍五入值。
- 使用1/4 Kelly作为仓位起点，单场所有推荐方向的含费投入合计不超过本金2%。
- 实际推荐必须为整数份，并重新计算该笔订单的取整手续费、EV和总成本。小订单可能不再达到初始100份筛查的门槛。
- 同一场多个方向相关。当前实现按独立二元Kelly计算再统一缩放至单场上限，不声称是联合组合Kelly最优解。
- 无真实价格、EV未达门槛、非正Kelly或资金不足时不生成可执行的合约数量；零价差示例仍可能列出估算建议，需补充真实ask后复算。

## 准确度与使用命令

Brier采用三分类平方误差之和，均匀基准为2/3，越低越好。对数损失采用自然对数，均匀基准为ln 3；给实际结果0概率时损失为无穷大，不暗中裁剪。命中数与期望命中数只统计已结算比赛，期望命中数为每场最高预测概率之和。首选比分和场均进球只使用已有对应赛果的比赛。

```bash
python scripts/football_ev.py ev --probs 0.35 0.31 0.34 --prices 30.5 28.5 47.8
python scripts/football_ev.py ev --probs 0.35 0.31 0.34 --prices 30.5 28.5 47.8 --bids 28 26 42 --bankroll 1000
python scripts/football_ev.py score football/predictions_log.csv
```

第一条命令是用户提供的计算示例：客胜No显示+12.1¢，主胜Yes显示+3.0¢，平局Yes显示+1.1¢且不推荐，客胜Yes显示−15.6¢。显示保留一位小数，使用四舍五入的 half-up 规则。当前九场尚未结算，评分应显示0场已结算、9场待结算，历史评分为N/A。
